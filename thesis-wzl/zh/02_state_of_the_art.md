# 第 2 章 移动操作臂全身运动规划研究现状

对应英文：`02_state_of_the_art.tex`。

上一章说：LMAS 需要全身运动规划，而不是底盘、手臂拆开的流水线。本章看文献怎么做，并把范围收到后文实际用的框架。第 2.1 节给移动操作臂运动规划分类。第 2.2 节聚焦**整体式**（全身）规划器，介绍 OCS2（第 2.2.1 节）和主要替代方案（第 2.2.2 节）。第 2.3 节对照 HERo 的需求，说明为什么选 OCS2。开源和应用方面的综述，部分依据同一研究项目里关于“把全身运动规划接到导航栈”的系统文献综述（Sant’Anna，2026）。

## 2.1 运动规划方法怎么分类

移动操作臂的运动规划可以沿几条大致独立的轴来分。该领域的系统综述（Sandakalum 与 Ning，2022；Thakar 等，2023）主要按**底盘和手臂怎么耦合**、以及**用什么算法生成运动**来分；第三条更偏实践：**计算发生在执行前还是执行中**。

**解耦 vs 全身。** 对本工作最重要的区分是解耦和全身。解耦：底盘和手臂分开、先后规划。导航栈先把底盘开到待机位姿，手臂规划器再在这个固定底盘构型上解操作任务。全身：底盘和手臂是**一套**冗余运动学（或动力学）系统，运动一起求，任务空间目标由规划器自己分给底盘和手臂。第 1.2 节已经说：解耦丢掉可达性、最优性和反应能力；全身把这些拿回来，代价是问题维数更高、耦合更紧。

**算法原理。** 不管怎么耦合，运动可以由不同族的算法产生：

- **采样规划：** 在构型空间里随机采样并连接无碰撞状态（例如 MoveIt 里的快速随机树 RRT、概率路图 PRM）。擅长在杂乱、高维空间里找到可行路径，但本身不算一条“沿途代价”，通常离线用。
- **优化规划：** 把运动写成轨迹上的约束优化。整条轨迹离线算一次，叫**轨迹优化**；在线按滚动时域反复求，就是 **MPC**。两者都能显式处理关节、速度、碰撞约束，并给出平滑、按代价最优的运动。
- **反应式方法：** 由当前状态立刻算一条指令，例如势场、基于二次规划的逆运动学（QP-IK）。便宜、快，但短视，看不了长时域约束。
- **学习方法：** 用（深度）强化学习得到的策略代替或增强规划器。可以把全身规划的在线计算摊掉，但有数据效率、安全、仿真到真机迁移的问题（Sant’Anna，2026）。

**离线 vs 在线。** 规划器可以**离线**——执行前算完整轨迹——或**在线**——状态估计和目标一更新就重规划。只有在线、带反馈的规划，才能在共享、变化的 LMAS 工作空间里抗扰动。全身 MPC 落在**全身、基于优化、在线**三者的交集，也就是本论文瞄准的区域。

## 2.2 整体式运动规划器概览

**整体式**（全身）规划器在一套公式里同时求底盘和手臂运动。实践里，成熟、能部署的代表几乎都是基于优化的：任务写成代价、物理限制写成约束，正好对上移动操作的耦合、冗余和约束。把这类控制器接到导航栈的系统综述发现：在“导航栈 + 真正的全身控制器”这类开源项目里，最优控制公式——尤其是 OCS2 工具箱——反复作为骨干出现，旁边还有操作空间控制、二次规划求解器，以及更近的学习策略（Sant’Anna，2026）。下面先写 OCS2，再把主要替代方案摆在它旁边。

### 2.2.1 OCS2：基于最优控制的模型预测控制

**OCS2**（Optimal Control for Switched Systems）是苏黎世联邦理工学院机器人系统实验室的开源 C++ 数值最优控制库。它为连续时间最优控制提供高效求解器——最突出的是序贯线性二次（Sequential Linear-Quadratic，SLQ）控制，即带约束的微分动态规划（DDP）——以及把它们当 MPC 跑起来所需的配套设施。

三点使 OCS2 很适合全身移动操作。第一，求解器要的代价和约束导数用**自动微分**得到：用户用符号写出模型（运动学、代价项、约束），OCS2 经 CppAD / CppADCodeGen 生成并编译高效导数代码。第二，它提供**参考管理器**，任务空间期望轨迹可以在线改，这正是“目标生成节点”去指挥控制器需要的接口。第三，对实时部署最关键：OCS2 用 **MPC–MRT 分离**把优化和执行拆开。MPC 进程按自己的频率解最优控制并发布一份**策略**；轻量的模型参考跟踪（Model Reference Tracking，MRT）客户端按控制频率评估这份策略，得到当前这一拍的指令。于是优化器和硬件接口可以是两个进程，甚至两台机器。第 3 章的分布式架构用的就是这一点。

OCS2 已在腿式和轮式平台的全身移动–操作上演示过，包括移动和操作合在一起的统一 MPC（Sleiman 等，2021），以及与带关节物体的感知全身交互（Mittal 等，2022）。同一项目综述还把它背后的非完整移动操作臂运动学规划、以及动态稳定移动操作臂全身 MPC，标成工具箱的核心移动操作文献。硬件上的使用记录、显式约束处理、以及进程可分离架构，使它成为 HERo 的首选。

### 2.2.2 替代框架和方法

OCS2 之外还有若干替代，覆盖第 2.1 节那些算法族。

**采样规划（MoveIt）。** MoveIt 是 ROS 生态里事实上的标准运动规划框架。强项是杂乱场景里冗余臂的离线无碰撞规划；把底盘位姿当成额外规划变量，也可以扩到移动底盘。但常见用法里，MoveIt 支撑的是**解耦**的“先导航再操作”流水线，本身并不提供全身 MPC 那种在线、协调的底盘–手臂反馈。所以它是本工作要离开的现有流水线，而不是另一个全身规划器。两种流水线的定量比较需要在同一平台上再实现一套解耦方案，留给后续工作（第 6 章）。

**其他优化 / MPC 工具。** 全身行为也可以用通用最优控制和 MPC 求解器，或基于约束的任务空间控制器来做。项目内部综述整理了把这类控制器接到导航栈的几种做法：用 `nav2_core::Controller` 插件换掉 Nav2 局部规划器、包进 `ros2_control`、或用 `cmd_vel` / 目标话题桥到全身求解器。这一类里 OCS2 和二次规划求解器占多数。它们技术上能做，但往往集成更重，或对本文针对的“差速底盘 + ROS 2 硬件栈”支持不如 OCS2 成熟。

**反应式二次规划逆运动学。** QP 逆运动学把末端任务和次级目标（躲关节限位、可操作性）在每个控制步解成关节速度。计算轻、反应快，但是单步方法，看不了时域上的约束，难以规划“路径比手臂够得着的范围更长”时的底盘–手臂协调。

**基于学习的全身控制。** 越来越多工作把经典导航和强化学习拼在一起，把全身规划的在线代价摊掉，学一个从观测直接到的底盘和手臂指令的策略。虽然有前景，但带来训练数据、可复现、仿真到真机迁移的问题，和本论文目标不合：近期要在真机上部署一个透明、可分析的控制器。

## 2.3 比较，以及为什么选 OCS2

HERo 规划器的选择由第 1 章的需求驱动：协调的全身运动；显式处理关节/速度、非完整、自碰撞约束；在线反应；在不算强的机载算力上实时可行；ROS 2 支持要好，才能接到现有硬件栈。表 2.1 是各候选相对这些准则的定性打分。

**表 2.1** 相对 HERo 需求的定性比较（+ 好，○ 部分满足，− 弱）

| 准则 | 采样（MoveIt） | QP-IK（反应式） | 学习（强化学习） | 全身 MPC（OCS2） |
|------|----------------|-----------------|------------------|------------------|
| 协调的全身运动 | ○ | ○ | + | + |
| 显式约束处理 | ○ | ○ | − | + |
| 在线反应 | − | + | + | + |
| 实时可行性 | ○ | + | + | ○ |
| 冗余消解 | ○ | + | + | + |
| ROS 2 成熟度 | + | ○ | − | + |
| 透明 / 可分析 | + | + | − | + |

采样规划成熟、支持好，但离线，标准形式下还是解耦——不能当主全身规划器，但仍是现有对照。反应式 QP-IK 快但短视。学习方法原则上吸引人，但和本工作“近期、先上真机、要可分析”冲突。全身 MPC 是唯一同时给出协调底盘–手臂运动、显式约束、在线反应的一类；主要缺点是在线解最优控制很重，可以用 MPC–MRT 分离和分布式部署（第 3 章）应对，并在第 5 章用实验量化。

在全身 MPC 的实现里，选 OCS2 是因为：开源实现成熟、约束支持明确、已在轮式和腿式移动操作臂上用过，以及对分布式硬件上实时部署最关键的一点——进程可分离的 MPC–MRT 架构。后文因此在 HERo 上集成并验证基于 OCS2 的全身 MPC。
